# Finance Bot

## Цель
Семейный Telegram-бот учёта финансов. Портфолио-проект для вакансий AI automation.

## Функции MVP
- Расход текстом, голосом, фото чека (ИИ разбирает и ставит категорию)
- Доходы
- Отчёт: доход против месячной цели, расходы по категориям
- Доступ для двух пользователей (я и жена)

## Стек
Node.js + TypeScript, grammY, Supabase, ИИ-API, Whisper, Docker, деплой на мой Ubuntu VPS

## Правила
- Секреты только в .env, .env в .gitignore
- Маленькие шаги, после каждого — проверка и коммит
- Комментарии в коде и README на английском (для портфолио)
- Перед любыми изменениями — сначала план, код только после моего «ок»
- Объясняй решения простыми словами: я учусь

### Известные проблемы (не исправлены — ждут «ок»)
- 🟠 Бот отвечает на любое сообщение от чужих (вектор для спама)
- 🟠 `ALLOWED_USER_IDS` при лишней запятой в `.env` тихо пропускает `0` как «разрешённый» ID
- 🟠 Access control не отличает личные чаты от групповых
- 🟡 `package.json` без `"private": true`
- 🟡 Имена файлов миграций не в формате Supabase CLI (`YYYYMMDDHHMMSS_name.sql`)
- 🟡 Состояние «жду выбор категории» / «жду имя новой категории» хранится в памяти процесса — при перезапуске бота (деплой, краш) потеряется, и нужно будет написать сообщение заново. Осознанный компромисс для MVP на двух пользователей, не баг
- 🟡 ИИ-классификация стоит денег и требует работающий биллинг на OpenAI — уже один раз ловили `insufficient_quota`, если баланс кончится — бот будет отвечать «не получилось обработать»

### Найденные и исправленные в этой сессии баги
- Промпт ИИ был излишне осторожен: не находя уверенную категорию, обнулял вообще все поля (включая сумму) — чинил явным разделением правил + примерами
- Supabase возвращает связанные записи (`author`, `category`) объектом, а не массивом; код читал их как массив (`row.category?.[0]?.name`) — молча получал `undefined` без ошибки. Из-за этого `/list` всегда показывал автора как «Неизвестно», а `/report` — все траты как «Без категории». Исправлено через явную типизацию реальной формы ответа (`.returns<T>()` / `.maybeSingle<T>()`)
